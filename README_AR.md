# نظام صيانة IPA Strong

## التركيب على GitHub

1. فك ضغط الحزمة على الحاسبة.
2. افتح مجلد IPA_Strong_Repair_System الموجود داخلها.
3. ارفع محتوياته إلى جذر مستودع ipastrong، بنفس الأسماء. لا ترفع ملف ZIP نفسه ولا المجلد الخارجي باسم جديد.
4. تأكد أن source_guard.py وmerge_sources.py وipastrong.json بجانب بعض، وأن الاختبار في tests/test_source_guard.py.
5. استبدل ملف التحديث القديم في .github/workflows/update-ipastrong.yml بالملف الموجود بالحزمة. لا تنشئ workflow ثانياً يعمل بالتوازي مع القديم.
6. اضغط Commit changes.
7. افتح Actions ثم Update and repair IPA Strong ثم Run workflow، واختر update ثم Run workflow.
8. بعد النجاح حدّث المصدر في BatSign. رابط المصدر لا يتغيّر.

لا تحذف ملفات موقعك أو شعارك أو إعدادات المصادر الموجودة. الحزمة تضيف ملفات الصيانة وتستبدل الملفات المذكورة فقط.

## ما يفعله النظام

- يجلب تحديثات المصادر كل ست ساعات؛ موعد GitHub المجدول قد يتأخر.
- يفحص حتى 400 رابط تحميل رئيسي في كل تشغيل، بالأقدم فحصاً أولاً. يستغرق المرور الأول على 8300 رابط حوالي خمسة أيام إذا اكتملت التشغيلات.
- يفحص أن الاستجابة تبدأ بتوقيع ZIP، ويقرأ أربعة بايتات فقط بدلاً من تنزيل الألعاب الكبيرة.
- لا يعتبر 403 أو 429 أو انتهاء المهلة دليلاً على حذف الملف.
- لا يغيّر رابطاً بسبب 404 واحد: يتطلب تأكيدين في تشغيلين يفصل بينهما نصف ساعة على الأقل.
- عند تأكد فقدان الملف، يختبر البدائل المسجلة لنفس التطبيق المعدّل ونفس الإصدار. لا ينقل المستخدم إلى تويك آخر أو إصدار أقدم تلقائياً.
- إذا لم يوجد بديل مؤكّد، يحتفظ بالتطبيق ويذكره في التقرير. لا يخترع روابط ولا يرفع ملفات جديدة من تلقاء نفسه.
- يحتفظ بالتطبيقات القديمة وإضافات المالك وتواريخ الإصدارات الحقيقية. لا يحذف التطبيقات لمجرد عمرها.
- يحتفظ بالإصدارات الموجودة سابقاً حتى لو حذفتها المصادر الخارجية من قوائمها.
- يحافظ على التصحيحات الموثقة في _downloadOverrides بعد تحديث المصدر.
- يفحص بنية JSON وتوافق حقول التطبيق مع الإصدار قبل النشر. عند الخلل أو فشل جميع المصادر يبقى الملف المنشور كما هو.
- يحتفظ بآخر ملف سليم مضغوطاً في backups/ipastrong.last-good.json.gz.
- إذا أصبح ملف المصدر تالفاً، يسترجع تلقائياً النسخة الاحتياطية بعد فحصها؛ إذا تلفت النسخة أيضاً، يوقف النشر ويظهر الخطأ.
- يمنع تداخل تشغيلين من workflow نفسه. إذا حصل تعارض git مع تعديل يدوي، يفشل الدفع بأمان؛ لا يستخدم force-push.

## التقرير والتراجع

- source-health-report.json: نتيجة آخر تشغيل ناجح، المصادر التي فشلت، الإصلاحات، والملفات التي تحتاج بديلاً.
- source-health.json: ذاكرة الفحص الدورية؛ لا ترفع فوقها نسخة قديمة بعد بدء التشغيل.
- إذا فشل التشغيل، افتح Actions وافتح التشغيل ونزّل source-diagnostics للاطلاع على السبب.
- للتراجع افتح Run workflow واختر rollback. يشترط وجود نسخة احتياطية سبق إنشاؤها بنجاح.
- تعديل الملف ونشره على GitHub لا يثبت التطبيق عند المشتركين؛ هم يحدّثون المصدر من التطبيق.

## حدود التحقق

الاستجابة برابط ZIP تعني أن الخادم يقدّم ملفاً أرشيفياً، ولا تثبت نجاح توقيعه أو تشغيله على كل أجهزة iPhone. لا يفحص النظام ميزات التطبيقات المعدلة أو توافق شهادتك، ولا يبدل الملفات المحذوفة بملفات من مواقع عشوائية. بعض مزوّدي الملفات يمنعون خوادم GitHub؛ تُسجّل الحالة دون حذف التطبيق.

## تشغيل محلي

Python 3.12 دون مكتبات إضافية:

    python3 -m unittest discover -s tests -p test_source_guard.py -v
    python3 source_guard.py --audit-limit 400

فحص الروابط دون جلب إصدارات جديدة:

    python3 source_guard.py --audit-only --audit-limit 20

استرجاع آخر نسخة:

    python3 source_guard.py --rollback
