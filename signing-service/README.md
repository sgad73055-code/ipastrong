# خدمة التوقيع (Signing Service)

توقّع ملف IPA بشهادة المستخدم نفسه (`.p12` + `.mobileprovision`) ثم تعيد رابط تثبيت `itms-services`. **لا تحتاج VPS** — تُنشر كحاوية Docker على Cloud Run (الخطة المجانية تكفي للاستخدام العادي).

## لماذا ليست ضمن Cloudflare Pages
التوقيع الحقيقي يشغّل برنامجاً ثنائياً (`zsign`) يعيد توقيع كل ملف تنفيذي داخل حزمة التطبيق. بيئة Cloudflare Workers/Pages Functions لا تُشغّل ملفات تنفيذية ولا تمنح وقت معالجة كافٍ لهذا، فالخدمة هذه منفصلة عمداً.

## الأمان
- كلمة المرور والشهادة تُستخدم داخل الطلب فقط، وتُحذف من القرص فور انتهاء التوقيع (نجح أو فشل) — انظر `src/server.js`.
- لا تسجيل (`console.log`) لأي محتوى من الطلب.
- رابط التنزيل الناتج عشوائي (128-bit)، صالح 10 دقائق أو مرتين تنزيل، ثم يُحذف نهائياً من القرص.
- `ipaUrl` (جلب IPA من الكتالوج مباشرة) يقبل فقط روابط HTTPS عامة، لا عناوين داخلية/IP.

## النشر على Google Cloud Run (مجاني لحد معقول من الاستخدام)
المتطلبات: حساب Google Cloud (بطاقة مطلوبة للتفعيل لكن لا خصم ضمن الحد المجاني)، و`gcloud` مثبت محلياً أو عبر Cloud Shell بالمتصفح (لا يحتاج جهازك).

```bash
# من داخل مجلد signing-service
gcloud auth login
gcloud config set project YOUR_PROJECT_ID
gcloud run deploy ipastrong-signer \
  --source . \
  --region europe-west1 \
  --allow-unauthenticated \
  --memory 2Gi --cpu 2 --timeout 300 \
  --set-env-vars ALLOWED_ORIGIN=https://ipastrong.pages.dev,MAX_BODY_MB=700
```

بعد النشر ستحصل على رابط مثل `https://ipastrong-signer-xxxxx-ew.a.run.app`. افتح `signer.html` في جذر الموقع وضع هذا الرابط في `SIGN_SERVICE_URL`، ثم انشر الموقع كالمعتاد.

`--memory 2Gi` ضروري لأن الخدمة تُحمّل كامل IPA في الذاكرة أثناء التوقيع (انظر "القيود" أدناه).

### بديل: Fly.io
نفس `Dockerfile` يعمل مباشرة: `fly launch` ثم `fly deploy` من هذا المجلد. اضبط نفس متغيرات البيئة عبر `fly secrets set`.

## الاختبار محلياً (بدون zsign حقيقي)
```bash
node --test test/*.test.mjs
```
يستخدم zsign وهمياً (`test/bin/fake-zsign.cjs`) للتحقق من منطق الخادم فقط (الحذف، الصلاحية، الحدود). **لم يُختبر التوقيع الفعلي هنا** لعدم توفر شبكة لبناء/تشغيل zsign الحقيقي في بيئة التطوير — اختبره على جهازك الحقيقي بعد النشر، بشهادة تعرف أنها صالحة.

## القيود المعروفة
- **لا يستخرج Bundle ID تلقائياً** من IPA مرفوع يدوياً؛ وضع "من الكتالوج" (عبر زر «وقّع بشهادتك الخاصة» في الموقع) يرسله تلقائياً من بيانات التطبيق. الرفع اليدوي يطلبه عبر `prompt()` بسيط — قد تحتاج تحسينه لاحقاً.
- **الشهادة يجب أن تطابق الجهاز**: Ad Hoc تحتاج UDID الجهاز مسجَّلاً في البروفايل مسبقاً؛ هذه الخدمة لا تتحقق من ذلك ولا تسجّل أجهزة في Apple، فقط توقّع بما تملكه أنت.
- **حجم الذاكرة**: تُحمَّل الملفات كاملة في الذاكرة (لا streaming حقيقي)؛ طبّقنا هذا عمداً لتبسيط الكود وتسهيل اختباره، على حساب استهلاك ذاكرة أعلى مع تطبيقات كبيرة (+1GB). إذا واجهت أخطاء ذاكرة ارفع `--memory`.
- **لا حماية ضد سوء الاستخدام** (rate limiting) بعد — أي زائر يملك شهادة صالحة يقدر يستدعي `/sign` عدد مرات غير محدود حالياً.
